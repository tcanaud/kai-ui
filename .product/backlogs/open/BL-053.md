The SMOKE1 test for feature 006 could not be fully executed end-to-end because the sidecar API returned an error ("Working tree is dirty. Commit or stash changes first.") when the test environment had uncommitted changes. The test was completed using a mocked fetch response, which means the session list refresh path could not be verified.

**Problem** (FB-078):
- Real POST `/api/sessions` rejects requests when the git working tree is dirty
- QA sessions frequently have uncommitted changes (test scripts, artifacts)
- E2E verification requires mocking, reducing confidence in real API behavior

**Suggested fix**:
- Add a `TEST_MODE=1` / `KAI_SKIP_GIT_CLEAN_CHECK=1` environment variable flag in the sidecar API that bypasses the git-clean check in test environments
- OR: provide a dedicated E2E test environment with a clean git snapshot (e.g., a git worktree or fixture repo)
- Either approach enables true end-to-end SMOKE1 verification without mocking

**Acceptance criteria**:
- SMOKE1 test can be executed end-to-end (real API call, real session creation, dialog close, session list refresh) without mocking.
- The git-clean check bypass is only active in explicitly designated test environments.
