Two UX gaps in the feature name input field within the session creation dialog:

1. **Silent truncation at maxLength** (FB-092): The input has `maxLength=100` but provides no feedback when the user reaches or exceeds the limit. Characters are silently dropped with no counter or warning.

2. **Generic validation error messages** (FB-093): All invalid feature name patterns (trailing hyphens, consecutive hyphens, leading hyphens, etc.) produce the same generic error message. Users don't know which rule they violated or how to fix it.

**File**: `new-session-dialog.tsx` — feature name `<Input>` and validation error display.

**Fix**:
- Add a live character counter showing `{current}/{max}` (e.g., "47/100") beneath the input, turning red as the limit approaches
- Enumerate validation rules and return specific messages per violation (e.g., "Name cannot start with a hyphen", "Consecutive hyphens are not allowed")
- Consider a `getSpecificValidationError(value: string): string` helper that returns the most relevant error
