Two minor UX gaps that leave users confused about intent and state:

**FB-034** — The "kai ui" header logo/text provides no visual feedback on click. It is unclear whether clicking it does anything (deselect session, navigate home, refresh). If it has a function it needs visible affordance (cursor, hover, active state); if it has no function it should not be interactive.

**FB-035** — When all panels are toggled off, the main content area shows a blank state with no guidance. Users may not understand why the content area is empty or how to restore panels.

**Fixes**:
- Clarify header click intent: add cursor and hover/active states if functional, remove interactivity if not.
- Add an empty-state message in the panel area when no panel is active: e.g., "No panel selected. Click a panel button above to display it." with a visual pointer to the toggle controls.

**Acceptance criteria**:
- Clicking the header has clear visual affordance consistent with its actual behavior.
- When zero panels are active, a helpful empty-state message is shown in the content area.
