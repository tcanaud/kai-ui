Four accessibility defects across dialogs, forms, and navigation that collectively violate WCAG 2.1 SC 4.1.2 (Name, Role, Value):

1. **FB-009 — Missing DialogTitle**: 4 `<DialogContent>` (Radix UI) components lack a `<DialogTitle>`, so screen readers announce the dialog opened but cannot identify its purpose. Add `<DialogTitle>` (with `className="sr-only"` if visually hidden where needed).

2. **FB-010 — Hamburger button no aria-label**: The mobile hamburger `Button` has no accessible name. Add `aria-label="Open session sidebar"` or an `sr-only` text child.

3. **FB-014 — Form fields missing id/name/label associations**: The Create Session dialog form inputs lack `id` and `name` attributes; `<label>` elements are not associated via `htmlFor`. Fix all three attributes on each form field.

4. **FB-022 — xterm.js helper textarea warning**: The `xterm-helper-textarea` lacks `id`/`name` attributes, generating a browser console a11y warning. Investigate xterm.js configuration options or a newer `@xterm/xterm` version.

**Acceptance Criteria**:
- All dialogs announce a meaningful name to screen readers
- Hamburger button announces "Open session sidebar"
- All form fields are correctly labelled and associated
- xterm.js console a11y warning is eliminated or suppressed with a rationale comment
