Two performance issues caused by xterm being loaded eagerly on initial page load:

1. **377 KiB unused JavaScript** (FB-062): Chrome DevTools coverage shows 377 KiB of xterm JS is parsed on initial load but never executed, because the terminal panel is not visible by default. This inflates Time to Interactive unnecessarily.

2. **Render-blocking xterm CSS** (FB-063): The xterm stylesheet is included in the critical CSS path even when the terminal is hidden, adding bytes to the initial render and delaying First Contentful Paint.

**Fix**: Lazy-load the entire terminal component using Next.js `dynamic()` with `{ ssr: false }`. This automatically defers both the JS (`import('@xterm/xterm')`) and the CSS import until the terminal panel is first rendered. Both issues are resolved together by a single lazy-load strategy.
