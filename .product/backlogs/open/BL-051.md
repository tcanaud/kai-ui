The 7 acceptance test scripts for feature 002 all require Chrome running with `--remote-debugging-port=9222` and the `ws` npm package. Two scripts additionally require interactive stdin to stop/restart the sidecar. These prerequisites make CI execution difficult without additional infrastructure.

**Problem** (FB-074):
- All `.qa/002-fix-terminal-websocket-initial-connection-failure/scripts/*.mjs` require Chrome remote debugging
- No headless/automated execution path
- Sidecar stop/restart tests require interactive stdin

**Suggested fix**:
- Migrate CDP-based tests to Playwright for headless execution
- Automate sidecar lifecycle within test scripts (spawn/kill child process) instead of relying on interactive input
- Alternatively, leverage MCP Chrome DevTools integration for non-CI testing contexts

**Acceptance criteria**:
- All QA acceptance tests for feature 002 can be executed in a CI environment without a manually started Chrome instance.
- Sidecar lifecycle (stop/restart) is managed programmatically within the test scripts.
