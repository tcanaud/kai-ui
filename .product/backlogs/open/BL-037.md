When loading the terminal panel, it displays stale output from a previous session or connection. There is no clear-on-connect behavior to reset the terminal display when a new WebSocket connection is established.

**Fix options**:
1. Send a `clear` sequence (`\x1b[2J\x1b[H`) to xterm.js on WebSocket `open` event.
2. Call `terminal.clear()` on the xterm instance at connection open.
3. Preserve scrollback but scroll to bottom — clear only when session is new vs. reconnect.

Consider making clear-on-connect a user-configurable option to support both "fresh start" and "resume session" use cases.

**Acceptance criteria**:
- Loading a new terminal session does not display stale output from a previous connection.
- Reconnects to an existing session can optionally preserve scrollback.
- Behavior is consistent and predictable across page reloads.
