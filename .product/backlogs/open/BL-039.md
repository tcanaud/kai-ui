The session creation submit handler uses `setLoading(true)` to disable the submit button, but React state updates are asynchronous. If the user double-clicks the submit button before the state update re-renders (disabling the button), multiple concurrent `createSession` requests can be fired, potentially creating duplicate sessions.

**Reproduction**: Fill the new session dialog and double-click the submit button quickly — two sessions may be created simultaneously.

**Fix**: Use a `useRef` guard (e.g. `const submitting = useRef(false)`) that is set synchronously at the start of the handler and cleared on completion. This prevents re-entry regardless of render timing, independent of React's asynchronous state scheduling.
