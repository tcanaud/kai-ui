Two related mobile interaction bugs affecting session selection UX:

1. **Touch off-by-one selection** (FB-087): On mobile, clicking a session in the Sheet component selects the item *above* the tapped item. Hit regions in `session-item.tsx` are misaligned within the Sheet component, likely due to incorrect bounding box or z-index stacking.

2. **Selection state reset on viewport transition** (FB-088): Switching from desktop to mobile viewport (e.g., via browser DevTools or orientation change) resets the active session to the first item, discarding the user's current selection.

Both issues degrade mobile usability and trust in the session sidebar navigation.

**Files likely involved**: `session-item.tsx`, `session-sidebar.tsx`, mobile Sheet wrapper.

**Fix**:
- Audit hit region alignment in Sheet for session items — verify padding/margin doesn't shift click targets
- Preserve selected session ID in state across viewport transitions (decouple selection from layout mode)
