Two ARIA regressions introduced by the feature-007 panel accessibility fix:

1. **role=button with interactive content** (FB-050): Panel divs were given `role="button"` to support keyboard activation, but the terminal panel contains interactive elements (xterm). Nesting interactive content inside `role="button"` is invalid ARIA and causes screen readers to misinterpret or skip the inner content. Fix: separate the expand/collapse affordance into a dedicated button in the panel header; remove `role="button"` from the panel wrapper that contains interactive content.

2. **aria-selected without listbox context** (FB-051): `SessionItem` components now use `aria-selected`, but the parent container has no `role="listbox"` (or `role="tablist"`). The `aria-selected` attribute is only valid in listbox, tablist, tree, grid, or treegrid contexts — without the correct parent role, screen readers ignore or misinterpret it. Fix: add `role="listbox"` to the sessions list container with `role="option"` on each item, or switch to tablist/tab semantics.

Both issues are direct regressions from the panel ARIA additions in feature-007 (released 2026-02-20).
