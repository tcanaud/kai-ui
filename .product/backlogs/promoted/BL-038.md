The session creation API has three related security vulnerabilities in its server-side input handling:

1. **Shell command injection** (FB-040): The `playbook` and `feature` parameters are passed directly into `exec()` without sanitization. An attacker can inject shell metacharacters (`;`, `&&`, `|`, `$()`, backticks) to execute arbitrary server-side commands. Fix: replace `exec()` with `execFile()` and an explicit argument array.

2. **No server-side format validation** (FB-041): Only a non-empty check is performed on `feature`. No allowlist regex, no character restrictions, no path traversal protection. Fix: validate against `/^[a-z0-9][a-z0-9-_]{0,99}$/` server-side and return HTTP 400 on failure.

3. **Client-side-only length limit** (FB-043): The `maxLength=100` HTML attribute is bypassable via direct API calls, allowing oversized payloads that can cause DoS or downstream failures. Fix: enforce max length server-side and return HTTP 400 if exceeded.

All three issues share the same root cause: the API route trusts client-supplied input without independent server-side validation. These must be fixed together as a security hardening pass on the session creation endpoint.
