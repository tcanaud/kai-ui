Three interconnected terminal rendering and layout failures caused by the xterm container not having proper height and overflow constraints:

1. **Garbled characters on all viewports** (FB-054): xterm's character measurement overflows its container, causing incorrect character cell dimensions and corrupted output. Fix: ensure the terminal container has explicit, bounded dimensions before the fit addon is applied. Call `fitAddon.fit()` only after layout is stable (e.g., in a `ResizeObserver` callback).

2. **xterm-screen overflow blocking adjacent panels** (FB-057): `PanelSlot` is missing `h-full` (or equivalent height constraint), allowing xterm to grow beyond its allocated grid cell and extend over the Playbook panel header, making it unclickable. Fix: add `h-full` and `overflow-hidden` to `PanelSlot` to contain xterm within its grid cell.

3. **xterm-viewport height 0px — scrollbar broken** (FB-058): The terminal container does not propagate its height to xterm's viewport element, resulting in a 0px height that prevents scrollbar rendering and breaks mouse/scrollbar-based scrolling. Fix: ensure the container has a defined height at all times; call `fitAddon.fit()` after any layout change. This is likely resolved once FB-057's PanelSlot fix lands.

All three issues share the same root cause: the PanelSlot/terminal container lacks proper CSS height constraints, causing xterm's internal sizing to fail.
