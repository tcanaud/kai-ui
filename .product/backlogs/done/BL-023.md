Three UX defects in the New Session dialog related to error surfacing, form lifecycle, and async request management:

1. **FB-004 — Non-actionable error on dirty git tree**: HTTP 500 from `POST /api/sessions` surfaces as "Session creation failed" — the real cause (dirty working tree) is not shown to the user. The error message should be propagated to the dialog.

2. **FB-005 — Form state not reset on dialog close**: Stale playbook selection, feature name, and error messages persist when the dialog is reopened. The `onOpenChange` handler needs a cleanup branch to reset all form state when `isOpen` is false.

3. **FB-012 — No AbortController on dialog close**: In-flight API requests continue after the dialog closes, risking state updates on an unmounted component. An `AbortController` should be used to cancel the fetch when the dialog closes.

**Acceptance Criteria**:
- Dirty git tree error displays: "Your git working tree has uncommitted changes. Please commit or stash them before creating a session."
- Reopening the dialog shows a clean empty form
- Closing the dialog while a request is in-flight cancels the request
