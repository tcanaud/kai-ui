The feature name input in the New Session dialog has three validation gaps that allow invalid names to reach the API and fail downstream at the filesystem or git layer:

1. **FB-006 — Special characters accepted**: Characters like `/`, `\`, `*`, `?`, `:`, `"`, `<`, `>`, `|` are accepted without error, but break git branch and filesystem path creation.
2. **FB-007 — Whitespace-only passes validation**: Spaces-only input satisfies `!featureName` check and enables the submit button.
3. **FB-011 — No max length**: Arbitrarily long names are accepted; no `maxLength` constraint exists on the input.

**Fix**:
- Add regex validation: `/^[a-z0-9][a-z0-9-]*$/`
- Change empty check to `!featureName.trim()`
- Add `maxLength={100}` to the input element
- Show inline validation errors for each case

**Acceptance Criteria**:
- Whitespace-only input keeps submit button disabled
- Special characters trigger an inline validation error
- Input enforces a maximum of 100 characters
