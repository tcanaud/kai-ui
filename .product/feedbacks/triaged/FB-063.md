The xterm stylesheet is included in the render-blocking critical CSS path even when the terminal is not visible. This adds unnecessary bytes to the initial page render and delays First Contentful Paint.

Fix: Import the xterm CSS dynamically alongside the xterm JS (see FB-062), or use `<link rel="preload">` with a JavaScript-driven swap, so xterm styles are only applied when the terminal component is actually loaded. This is naturally resolved if the terminal component is fully lazy-loaded via Next.js `dynamic()`.
