**Severity**: Low

**Reproduction Steps**:
1. Open the New Session dialog
2. Inspect the form fields in the accessibility tree or browser DevTools
3. Check if `<label>` elements are correctly associated with their inputs via `for`/`id` attributes

**Expected**: Each form field should have an `id`, a matching `<label for="...">`, and a `name` attribute for correct semantic HTML and screen reader association
**Actual**: Form fields are missing `id` and `name` attributes. Label associations via `for` are mismatched or absent. Screen readers cannot correctly announce which label belongs to which input.

**Fix Suggestion**: Add `id` and `name` attributes to each form input in the Create Session dialog. Ensure each `<label>` has a matching `htmlFor` attribute pointing to the corresponding input's `id`.

**Source**: QA session — accessibility audit.
