**Severity**: low
**Context**: responsive-test QA session

## Description

On mobile, tapping "New Session" from the open navigation Sheet may display both the Sheet and the New Session dialog simultaneously. The `NewSessionDialog` component does not have an `onBeforeOpen` prop and does not call it when opening. The full prop-threading chain required for sequential close-then-open behavior is absent.

## Reproduction Steps

1. Open the app at a mobile viewport (≤ 768px)
2. Open the mobile nav Sheet via the hamburger button
3. Tap "New Session" from the Sheet
4. **Observed**: Both the Sheet and the New Session dialog may be visible simultaneously.
5. **Expected**: The Sheet closes first, then the New Session dialog opens.

## Root Cause

Missing prop-threading chain:
- `MobileNav.handleCloseSheet` is not passed as `onNavigate` to `SessionSidebar`
- `SessionSidebar` has no `onNavigate` prop
- `NewSessionDialog` has no `onBeforeOpen` prop and does not call it when `isOpen` becomes `true`

## Suggested Fix

Implement the `onBeforeOpen` callback chain:
1. Add `onBeforeOpen?: () => void` to `NewSessionDialogProps`
2. Call `onBeforeOpen?.()` in `handleOpenChange` when `isOpen=true`
3. Add `onNavigate` prop to `SessionSidebar` and thread it as `onBeforeOpen` to `NewSessionDialog`
4. Pass `handleCloseSheet` as `onNavigate` from `MobileNav` to `SessionSidebar`
