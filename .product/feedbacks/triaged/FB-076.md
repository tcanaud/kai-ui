**Test Script**: `.qa/003-fix-mobile-responsive-layout-sheet-close-failure-and-tablet-breakpoint/scripts/test-new-session-closes-sheet-first.sh`
**Criterion**: US3.AC1 — "Given the mobile nav sheet is open, When the user taps 'New Session', Then the sheet closes before the New Session dialog opens (no simultaneous sheet + dialog)."
**Observation**: `NewSessionDialog` does not have an `onBeforeOpen` prop, does not call `onBeforeOpen?.()` when opening, `SessionSidebar` has no `onNavigate` prop, and `MobileNav` does not pass `handleCloseSheet` as `onNavigate`. The full prop-threading chain required by the acceptance criterion is absent. This means on mobile, tapping "New Session" from the open sheet may display both the sheet and the dialog simultaneously.
**Severity**: non-blocking
**Suggestion**: Implement the `onBeforeOpen` callback chain: add `onBeforeOpen?: () => void` to `NewSessionDialogProps`, call it in `handleOpenChange` when `isOpen=true`, add `onNavigate` prop to `SessionSidebar` and thread it as `onBeforeOpen` to `NewSessionDialog`, and finally pass `handleCloseSheet` as `onNavigate` from `MobileNav` to `SessionSidebar`.
