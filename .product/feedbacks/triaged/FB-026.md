**Severity**: LOW

The API server returns HTTP 500 (Internal Server Error) for business logic validation errors such as "Working tree is dirty". These are expected, user-actionable conditions that should return 400 Bad Request or 422 Unprocessable Entity.

**Impact**: Clients cannot distinguish between true server errors and user-fixable validation failures. Monitoring tools will alert on 500s that are actually normal rejection cases.

**Example**: Attempting to create a session when the git working tree has uncommitted changes returns 500 instead of 422.

**Fix**: Audit API route handlers and return appropriate 4xx status codes for all business logic rejections. Reserve 500 for unexpected/unhandled errors only.

**Note**: Related to FB-004 (session creation HTTP 500 with non-actionable error message) but focuses specifically on the incorrect status code classification rather than the UX error message.
