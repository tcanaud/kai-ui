The `setLoading(true)` call in the session creation handler is asynchronous. If the user clicks the submit button rapidly before the state update renders (disabling the button), multiple concurrent `createSession` requests can be fired.

Reproduction:
1. Open the new session dialog.
2. Fill in all required fields.
3. Double-click the submit button quickly.
4. Observe that two sessions may be created simultaneously.

Fix: Use a `useRef` guard (e.g. `const submitting = useRef(false)`) that is set synchronously at the start of the handler and cleared on completion, preventing re-entry regardless of render timing. Alternatively, disable the button with a ref-based approach rather than relying solely on state.
