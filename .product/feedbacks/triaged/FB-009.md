**Severity**: Medium

**Reproduction Steps**:
1. Open any dialog in the app (e.g., New Session)
2. Inspect with a screen reader or check the browser accessibility tree
3. Observe that the dialog has no accessible title announced

**Expected**: Each dialog should have a `<DialogTitle>` element or equivalent `aria-label`/`aria-labelledby` so screen readers announce the dialog's purpose when it opens
**Actual**: 4 occurrences of `<DialogContent>` (Radix UI) are missing a corresponding `<DialogTitle>`. Screen readers will announce the dialog opened but without any name, failing WCAG 2.1 SC 4.1.2.

**Fix Suggestion**: Add `<DialogTitle>` (visually hidden if needed with `className="sr-only"`) to each `<DialogContent>` in the app. Also add `<DialogDescription>` or `aria-describedby` to resolve the related console warning: `Warning: Missing Description or aria-describedby={undefined} for {DialogContent}`.

**Source**: QA session — accessibility audit.
