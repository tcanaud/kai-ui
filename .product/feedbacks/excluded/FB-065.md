**Severity**: medium
**Context**: panel-interaction, keyboard-a11y QA session

## Description

The Terminal panel `<div>` has `tabIndex=-1` and no `role` attribute, making it unreachable via keyboard Tab navigation. All other 4 panels (Editor, Playbook, Chat, Assistant) correctly implement `role="button"` and `tabIndex=0`. This is a WCAG 2.1.2 violation — keyboard-only users cannot activate the Terminal panel.

## Reproduction Steps

1. Open the app with a session selected
2. Press Tab repeatedly to cycle through interactive elements
3. **Observed**: Terminal panel is skipped; it cannot receive focus via Tab.
4. **Expected**: All five panels (Terminal, Editor, Playbook, Chat, Assistant) should be reachable via Tab in order.

## Root Cause

The Terminal panel `<div>` wrapper is missing `role="button"` and `tabIndex={0}` attributes that are present on the other four panel wrappers. Also needs a `keydown` handler for Enter/Space to match the other panels.

## Suggested Fix

Add `role="button"` and `tabIndex={0}` to the Terminal panel `<div>` in the panel grid component, consistent with the other four panels. Wire up an `onKeyDown` handler for Enter/Space the same way as the other panels.

Note: Mouse clicks on the Terminal panel still work — `aria-pressed` toggles correctly. This is keyboard-only.
