**Severity**: low
**Context**: session-creation-adversarial QA session

## Description

The feature name input has `maxLength=100` as an HTML attribute, but there is no JavaScript-level or server-side validation enforcing a maximum length. A client that bypasses the HTML attribute (e.g., via API call or browser devtools) could submit an arbitrarily long feature name that could cause filesystem or git path issues.

## Reproduction Steps

1. Open the "New Session" dialog
2. Using browser devtools, remove the `maxlength` attribute from the input
3. Type or paste a very long string (>100 characters) into the feature name field
4. Submit the form
5. **Observed**: The API accepts the long name without a length validation error.
6. **Expected**: The server returns a 400/422 error indicating the name exceeds the maximum length.

## Suggested Fix

Add server-side validation in the POST `/api/sessions` handler to check that `featureName.length <= 100` and return a 400/422 with a descriptive error message if exceeded. Also add a JS-level check in the form's `onSubmit` handler as a defense-in-depth measure.
