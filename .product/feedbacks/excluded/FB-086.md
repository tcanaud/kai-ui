**Test Script**: Manual exploratory test via Chrome DevTools MCP
**Criterion**: Sheet close button must work on touch devices
**Observation**: Through controlled A/B testing with viewport emulation at 375x812:
- `hasTouch: false` (mouse pointer): X button click closes sheet immediately. PASS.
- `hasTouch: true` (touch emulation): X button click does NOT close sheet. Focus moves to dialog element but state remains `data-state="open"`. FAIL.
- Programmatic `element.click()` works in both modes.
- Full pointer event sequence (`pointerdown` + `pointerup` + `click` with `pointerType: 'touch'`) dispatched via JS also works.
- Escape key works in both modes.
- Overlay backdrop click works in both modes.
- Session item clicks correctly close the sheet in both modes.

This isolates the root cause to the Radix Dialog Close button's event handling when touch events are active. The button is 16x16px with no padding, which combined with the touch event handling issue makes it effectively non-functional on real touch devices.
**Severity**: non-blocking (workarounds exist: overlay click, Escape key, session item selection)
**Suggestion**: (1) Increase the Close button touch target to minimum 44x44px per WCAG 2.5.5. (2) Investigate whether the `onContextMenu={(e) => e.preventDefault()}` on the parent shell or the Radix Dialog's internal `onPointerDownOutside` handler is interfering with touch click synthesis on the Close button. Consider adding an explicit `onClick` handler on the Close button that calls `onOpenChange(false)` as a fallback.
