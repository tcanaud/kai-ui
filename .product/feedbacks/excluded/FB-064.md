**Severity**: medium
**Context**: sidebar-exploration QA session
**Scenario**: Mobile viewport (375x812), touch emulation enabled

## Description

The Radix Dialog Close (X) button inside the mobile nav Sheet does not respond to touch events. Mouse clicks work correctly but touch events do not close the sheet.

## Reproduction Steps

1. Open the app at a mobile viewport (≤ 768px)
2. Open the mobile nav Sheet via the hamburger button
3. Enable touch emulation in Chrome DevTools (hasTouch: true)
4. Tap the X close button in the top-right corner of the Sheet
5. **Observed**: Sheet remains open. Focus may move to the dialog element but `data-state` stays `"open"`.
6. **Expected**: Sheet closes and only the hamburger button is visible.

## Root Cause

Touch event synthesis issue with the Radix Dialog Close button's event handling when touch events are active. The Escape key, overlay backdrop click, and session item clicks all close the sheet correctly in touch mode.

Additionally, the X icon button is `size-4` (16×16px) with no touch target padding — well below the WCAG 2.5.5 minimum of 44×44px, making it effectively non-functional on real touch devices.

## Additional Notes

- `hasTouch: false` (mouse): X button click closes sheet. PASS.
- `hasTouch: true` (touch emulation): X button click does NOT close sheet. FAIL.
- Programmatic `element.click()` works in both modes.
- Full pointer event sequence dispatched via JS also works.
- Possible interference from `onContextMenu={(e) => e.preventDefault()}` on the parent shell or Radix's `onPointerDownOutside` handler.

## Suggested Fix

1. Increase the Close button touch target to minimum 44×44px (`min-h-11 min-w-11`) per WCAG 2.5.5.
2. Add an explicit `onClick` handler on the Close button that calls `onOpenChange(false)` as a fallback for touch devices.
