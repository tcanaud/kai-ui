**Severity**: low
**Context**: console-network-audit QA session

## Description

The terminal input field (the xterm.js helper textarea used for keyboard input) lacks `id` and `name` attributes. This prevents browser autofill functionality and may also produce accessibility warnings. (Note: the xterm.js internal helper textarea may not be directly controllable — this may require an xterm API workaround or wrapper approach.)

## Reproduction Steps

1. Open the app with a session selected so the terminal panel is active
2. Inspect the DOM for the xterm helper textarea element
3. **Observed**: The textarea has no `id` or `name` attribute.
4. **Expected**: The textarea has an `id` and `name` attribute (e.g., `id="terminal-input"`, `name="terminal-input"`).

## Suggested Fix

If xterm.js exposes a way to set attributes on its internal textarea, set `id` and `name` after terminal initialization. If not, consider wrapping with a custom approach or filing an upstream xterm.js issue. At minimum, suppress browser autofill with `autocomplete="off"` on the internal textarea element to prevent unwanted autofill suggestions.
