Server API route.ts line 79 passes the `playbook` and `feature` parameters directly into `exec()` without any sanitization. An attacker can craft a session creation request with shell metacharacters (`;`, `&&`, `|`, `$()`, backticks, etc.) in these fields to execute arbitrary shell commands on the server.

Reproduction:
1. Send a POST request to the session creation API endpoint with `feature` set to `"; rm -rf /tmp/test; echo "`.
2. Observe that the injected command is executed server-side.

Fix: Use `execFile()` with an explicit argument array instead of `exec()` with string interpolation, or sanitize/escape all user-supplied values before constructing shell commands. Never concatenate user input into shell strings.
