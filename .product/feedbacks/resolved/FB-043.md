The `maxLength=100` constraint on the feature name input is enforced only on the client side (HTML attribute). A direct API call bypasses this limit entirely, allowing arbitrarily long strings to be submitted to the server. This can lead to DoS via oversized payloads or unexpected behaviour in downstream processing (e.g. shell command length limits, filesystem path limits).

Fix: Enforce a maximum length (e.g. 100 characters) server-side in the API route handler and return a 400 error if the limit is exceeded.
