The session creation API only validates that the `feature` field is non-empty. It does not enforce any constraints on format, allowed character set, or length beyond that. This allows values containing special characters, path traversal sequences (`../`), unicode control characters, or excessively long strings to pass server-side checks.

Fix: Add a server-side allowlist regex for the feature name (e.g. alphanumeric + hyphens/underscores, max 100 chars). Return a 400 error with a descriptive message when the format is invalid.
