**Severity**: Medium

**Reproduction Steps**:
1. Ensure the git working tree has uncommitted changes (`git status` shows dirty state)
2. Open the New Session dialog
3. Select a valid playbook (e.g., "backlog-to-pr") and enter a feature name (e.g., "test-session-creation")
4. Click "Create Session"

**Expected**: Either a clear user-facing error explaining the git state requirement, or the API handles the dirty tree gracefully
**Actual**: `POST /api/sessions` returns HTTP 500 with `"Error: Working tree is dirty. Commit or stash changes first."`. The dialog displays the generic message "Session creation failed" — not actionable for the user.

**Notes**: The API itself is correct in surfacing the error, but the UI swallows the underlying reason. The user-visible error should reflect the actual cause: "Your git working tree has uncommitted changes. Please commit or stash them before creating a session."

**Source**: QA session — manual browser test, New Session happy path. Test criterion: session creation dialog closes and session appears in sidebar.
